NowBuild.ai｜营销项目协作 Agent

www.nowbuild.ai｜代码 github.com/JackZhong1998/N0707

  • 产品洞察：营销工作天然是多线程的——调研、策略、内容、投放反馈交织；用户不需要管理一堆对话窗口，需要的是一个项目级入口，把碎片意图汇总成可推进的任务流。
  • 架构设计：单入口 Router 承接用户意图，后台按工作类型调度不同执行 Agent（市场调研、策略推导、内容生成、竞品分析）；对用户呈现统一的项目进度与任务列表，而非多个割裂的对话。
  • 上下文管理：项目级上下文持久化——品牌资料、历史决策、已生成内容、用户偏好自动进入后续执行；新一轮对话不用重复交代背景，Agent 基于项目记忆续作。
  • 协作机制：低风险的调研与草拟直接执行并展示过程；涉及对外发布、预算决策时暂停并请求确认；长任务拆为可见节点，中断后从最近节点续跑。

todoAgent｜任务上下文 Agent

www.todoagent.cc｜代码 github.com/JackZhong1998/todoagent

  • 产品洞察：普通待办只存「做什么」，通用对话只存「聊了什么」；真正驱动 Agent 干活的是任务上下文——目标、约束、验收标准、相关材料——而这些在现有工具里都是缺失的。
  • 架构设计：每条待办是一个独立的上下文容器，Agent 先读取任务全貌再决定执行路径；Router 根据任务类型选择合适的执行策略（检索、生成、调用外部工具），而非一个 Prompt 打天下。
  • 上下文工程：目标、背景、约束、完成标准、历史讨论全部绑定到任务；区分「用户已确认的要求」和「Agent 自行推断的假设」，后者在执行前显式标注并请用户确认。
  • 人机协作：分析哪些步骤适合 AI 完成、哪些需要用户判断；先给建议与依据，用户确认后再执行；完成后的任务沉淀为可复用 SOP，相似任务下次直接参考已确认做法。

VoiceMind｜实时语音 Super Agent

www.voicemind.cc｜代码 github.com/JackZhong1998/voicemind

  • 产品洞察：语音在创作场景中承担双重角色——既是用户梳理思路的外化出口，也是向 Agent 下达任务的命令通道。现有产品把语音只当转文字，割裂了「想」和「做」的连续性。
  • 架构设计：采用 Router + Execution Agent 分离——前台 Router Agent 实时监听语音流，判断这段话是「待整理的想法」还是「要执行的指令」；后台挂载多个执行 Agent（待办生成、文档撰写、思维导图构建），Router 将意图分发到对应执行 Agent，做到言出法随：说完即出结果。
  • 上下文与状态：语音流是连续的，用户随时会补充、修正、推翻前一句；设计上让 Router 维护一份动态任务上下文，新指令只更新受影响的部分，不中断正在进行的执行，也不让旧结果覆盖用户刚改变的方向。
  • 协作体验：用户不需要在「记录想法」和「开始执行」之间切换——边说边整理为结构化产出（待办、文档、思维导图），随时插话、暂停、改方向；产出可编辑、可继续语音迭代。
